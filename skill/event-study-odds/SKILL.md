# 事件研究與賠率計算

把「跌得夠多了，能不能買」這種直覺問題，翻譯成可驗證的機率、賠率與期望值。

輸出的不是一個「會漲/會跌」的判斷，而是：**在什麼價位、用多寬的止損、博多大的目標，歷史上的勝率與淨期望是多少，以及這個數字是否值得相信。**

---

## 一、能力範圍

### 擅長（已用真實數據驗證）

| 能力 | 具體產出 |
|---|---|
| **位置判斷的量化** | 「在 X 價位進場，20 日內達標/被掃的機率各是多少」 |
| **止損幾何** | 用 ATR 校準止損寬度，找出「再放寬已無邊際收益」的拐點 |
| **期望值比較** | 把「博反彈」拆成 16 組止損×目標的淨期望矩陣 |
| **真假破位分辨** | 收盤破位（趨勢延續）vs 盤中破收盤收回（反轉試探），兩者結論相反 |
| **Alpha 歸因** | 區分「這是個股 Alpha」「板塊 Beta」還是「大盤/利率的地心引力」 |
| **形態效力檢驗** | 某個形態在你關心的板塊上，到底有沒有超額報酬 |
| **倉位換算** | 由風險預算反推手數，含連續虧損情境 |
| **偏誤偵測** | 倖存者偏差、時期偏差、事件重複計數、樣本量不足 |

### 有條件能做（必須聲明限制）

- **支撐位**：給的是「階梯 + 觸及概率」，不是一個精確價位。任何說「支撐就是 2.07」的答案都是過度自信。
- **時間預測**：給的是「20 日內曾觸及的機率分布」，不是「什麼時候會漲」。
- **目標價**：由 MFE 分布反推，不是由估值模型反推。

### 不做（會明確拒絕或轉交）

| 不適用 | 原因 / 轉交 |
|---|---|
| 基本面估值、DCF、PE 分位 | 走 `wb-finance-skill` 的估值 reference |
| 重大事件驅動的跳空（財報、併購、政策） | 歷史分布無法涵蓋結構性斷裂 |
| 新股（歷史 <2 年，事件 <10） | 樣本不足，只能當軼事 |
| 日均成交極低的標的 | 滑價模型失效，機率全是幻覺 |
| 衍生品、槓桿 ETF、窩輪牛熊證 | 有波動衰減與路徑依賴，本框架不適用 |
| 跨板塊移植形態結論 | 已證偽，見下方「鐵律」 |

### 已驗證邊界（誠實標註）

本 skill 的方法在以下範圍被實際驗證過：

- **標的**：2 隻港股深度研究（01164、09696）
- **板塊合併**：鈾礦/核能 13 標的、鋰礦/鋰電 15 標的
- **市場**：港股（騰訊）、美股/ETF（Yahoo）
- **未測**：A 股、日股、歐洲、加密貨幣、期貨、可轉債

在未測市場上，方法是可用的，但**所有參數（成本、冷卻期、事件閾值）都要重新校準**，且必須在報告中說明這是首次應用。

## 二、五條心法

這五條是這個 skill 的骨頭。偏離它們，後面的計算再精緻也是垃圾。

1. **概率只能從逐日數列算，不能從搜索摘要算。**
   摘要給的是「近期跌了不少」，統計要的是每一天的 OHLC。

2. **先問「這是不是比什麼都不看更好」。**
   隨機進場基準是照妖鏡。訊號沒有贏過它，就沒有 Alpha——此時正確結論是「沒有依據」，不是「再找個理由」。

3. **一個標的的勝率是故事，一組合併樣本才是統計。**
   單標的 n<10 算出來的 66.7%，和拋硬幣三次得到兩個正面沒有區別。

4. **分年拆開，否則牛市樣本會替你撒謊。**
   合併 2018–2026 的 52.4% 勝率，可能藏著近三年只有 46% 的事實。

5. **Alpha 屬於板塊與週期，不屬於形態。**
   「假破位」在鈾礦 T+20 +6.62%、在鋰礦只有 +0.52%（低於隨機 +2.39%）。同一個形態，兩個世界。

## 三、工作流

### Step 0：先分類標的狀態（決定用哪套事件）

**四種狀態：探底／磨底、破位下行、弱勢盤整、上升趨勢中的回調。** 跳過這步會得到相反結論。

每種狀態的特徵與對應事件（G/N、F/S、WR、A/B）只在
[`references/event-library.md`](references/event-library.md) 的「零、標的狀態分類」維護——
這裡不重複列表，避免兩處措辭分叉（2026-11 就發生過一處改成四種、另一處還寫三種）。

### Step 1：抓逐日 OHLC

```bash
python scripts/market_data.py hk01164 --start 2015-01-01 --out 01164.json --verbose
python scripts/market_data.py US:URNM --range 10y --out urnm.json
python scripts/market_data.py quote hk01164
```

**強制檢查**：印出的 `n` 與首尾日期。沒有確認首尾日期，不准進入統計。

交易時段內必須補當日盤中 K，否則「當前狀態」是昨天的：

```bash
python scripts/event_study.py 01164.json --intraday=hk01164 --profile
```

`--intraday` 會抓即時報價並補一根當日 K（含成交量）；未補時，`--profile` 會明確標示「某日收盤、非即時」。

端點細節、`cnt=1500` 上限、分段回溯、A 股限制 → `references/data-sources.md`

### Step 2：算指標與快照

```python
# ⚠️ 以下 import 需要 scripts/ 在 sys.path 上。兩種做法：
#   (a) cd skill/event-study-odds/scripts 後執行
#   (b) 在 repo 根目錄：
import sys; sys.path.insert(0, "skill/event-study-odds/scripts")
from indicators import compute_all, summary_at
I = compute_all(rows)          # MA/BOLL/RSI/KDJ/MACD/ATR/prior_low
summary_at(rows)               # 印最後一日的技術快照
```

**ATR 是核心尺度。** 所有止損寬度都要換算成「幾個 ATR」再比較。止損 <1.2×ATR 幾乎必然被噪音掃掉。

**口徑聲明**：本地自算，與第三方平台可能有小數級差異（MACD 柱採 `2*(DIF-DEA)` 中文慣例）。報告中若引用第三方數值，需說明來源與日期。

### Step 3：定義事件並去重

```python
from event_study import build_events, EVENT_SPECS
ev = build_events(I, "G", cooldown=10)
```

- **必須去重**：10 個交易日冷卻期，只留每簇首日。不去重虛增樣本約 24%。
- **必須同時算 4–5 組事件**。若各組方向不一致，正確答案是「沒有穩定結論」。
- **跑完先看 F 與 G 的 n**。若為 0，先懷疑 `prior_low` 算成了「含當日」。

九個基礎事件 + 三個 2026-11 新增的狀態事件（R1 / R2 / WR）的精確定義、`prior_low` 的致命 bug → `references/event-library.md`

### Step 4：前向報酬分布

```python
from event_study import forward_stats
forward_stats(rows, ev, horizons=(5, 10, 20, 40))
```

必須含 **n / 均值 / 中位 / P25 / P75 / 勝率 / MFE / MAE**。
均值與中位差距 >2pp 時，以中位為主敘述。

### Step 5：路徑模擬（核心）

```python
from event_study import path_matrix, path_stats
path_matrix(rows, ev, stops=(-5,-7,-9,-12,-15,-18), targets=(8,12,16,20,25))
```

三條鐵律：

1. 基準是**各事件自己的收盤價**，套百分比障礙。**絕不可寫死進場價。**
2. 同日同時觸及目標與止損 → 判止損。
3. 必須扣成本（港股來回約 0.75%）。

### Step 6：隨機進場基準

```python
from event_study import baseline_indices
base = baseline_indices(len(rows), step=20)
```

同一套路徑模擬、同一組止損目標。**若事件沒有贏過它，就說「沒有統計依據」。**

CLI 的路徑矩陣現在會為**每一格**附上同參數的隨機基準，直接印出超額 pp 與裁決（「無 Alpha」／「負期望」／「有超額」）。不需要自己補寫 import。

### Step 7：跨標的合併

選 8–15 個同產業標的（ETF + 龍頭 + 中小型），同一事件定義分別取事件後合併。
同時報「單標的 vs 合併」兩組數字，讓偏差幅度可見。

實測：只跑 URA 得勝率 76.5%，擴大到 13 標的後掉到 56.3%。**這就是倖存者偏差的幅度。**

### Step 8：三項偏誤檢查（必做）

```python
from event_study import year_split, break_sequence, classify_breaks, seq_stats, volume_profile
```

對應的 CLI（不必自己寫 import）：

```bash
python scripts/event_study.py 01164.json --years                 # 分年勝率
python scripts/event_study.py 01164.json --cooldown-sweep=5,10,20 # 冷卻期敏感度（每個 cd 各印一張網格）
python scripts/event_study.py 01164.json --cooldown=20            # 固定 cd=20，只印一張矩陣
python scripts/event_study.py 01164.json --breaks                # 破位序列（自動標註樣本不足）
```

**`--cooldown` 與 `--cooldown-sweep` 不是同義詞**：前者固定一個冷卻期、輸出**一張**矩陣；後者對清單裡每個冷卻期各輸出**一張同網格**矩陣，用來看「哪一格在哪個 cd 轉正」。兩者都吃 `--stops/--targets`；不帶時用 CLI 預設 **3×2**（−9/−12/−15% × +12/+16%，`--help` 會印出實際值），要對齊報告九格就明確帶 `--stops=-9,-12,-15 --targets=10,15,20`。

`summary_table` 會在事件 n<30 時自動附分年表；路徑矩陣在可用樣本 n<30 時自動附冷卻期敏感度。**冷卻期不是中性參數**：實測 01164 的 N 事件（`--stops=-12 --targets=12`）在 5/10/20 日冷卻期下，淨期望從 **+5.23%**（cooldown=10）擺盪到 **+1.03%**（cooldown=20），差距 4.2pp。用預設 `-9/+12` 則是 2.50 / 3.38 / 1.70（區間僅 1.68pp）——**引用這個例子時必須一併寫出止損／目標參數**，否則讀者用預設指令重現不出 4.2pp。

| 檢查 | 回答什麼 | 紅線 |
|---|---|---|
| **分年勝率** | 是不是被早年牛市拉高 | 近三年 <50% → 不得用整體數字進場 |
| **破位序列序號** | 「跌這麼多次該近了嗎」 | **單一標的觀察，不可當通則**：01164 實測 8 個桶全部 n<10（總事件 31 次），且形狀與舊口徑相反（第 1 次最好、第 7 次最差）。各桶 n<10 時只能說「沒有結論」 |
| **成交分布** | 上方套牢多厚、下方是否真空 | 上方 >80% → 反彈每一步都逆風 |

### Step 9：倉位與成本

```
手數 = (總資金 × 單筆風險%) ÷ (進場價 × 止損% × 每手股數)
```

同時報連續虧損情境（被掃率 37.5% → 連三掃約 5.3%）。
若合理倉位 <1 手，正確結論是「波動相對你的資金太大」，不是「放寬止損讓它能買」。

成本明細、樣本量門檻 → `references/statistics-protocol.md`

### Step 10：報告與自檢

```bash
python scripts/verify_report.py report.html
```

必須看到 `全部通過`（exit 0）。**若顯示「部分通過，需人工確認」（exit 2），代表有檢查被跳過或觸發警告**（例如找不到 node、報告未用 `var/window` 數列、價位宣稱落在數列窗口之外），不得當作已驗證。

⚠️ **`verify_report.py` 需要 Node.js**（用 `node --check` 校驗報告的內聯 JS）。沒有 node 時該項會 `[SKIP]`、整體 exit 2——這不是通過。四支分析腳本不需要 node。

exit 2 的處理政策（二選一，不可默默放行）：

- **新報告**：必須 exit 0 才交付。有 SKIP 就補資料（加 `var/window` 數列）或補 node，不要靠人工判斷硬過。
- **舊報告**：可交付 exit 2，但必須逐項寫下 SKIP 原因與人工確認結果（例如「價位對照 SKIP：該報告的價位只出現在圖表軸標籤，正文無可解析宣稱」），並在對應 README 標明「未通過自檢的項目」。**禁止把 SKIP 改寫成 PASS**。

`[INFO]` 一般不影響 exit code：它代表「這條宣稱無法用現有數列自動驗證」（例如引用比數列窗口更早的低點、分析師目標價、缺少進場價的止損），已印在終端，需人工看一眼。

**例外：價位歸屬不明。** 雙標的報告中若某條價位前方 600 字內沒有任何標的提及，自檢器不猜它是哪一檔，列 INFO 並計入 **exit 2**（未執行的檢查：「價位歸屬不明」）。正確做法是在價位前寫明代號或公司名，不是手動放行。

自檢器現在分兩層：

- 渲染層：JS 語法、數列長度、重複鍵（含嵌套物件）
- 財務啟發式：
  - 同一指標是否出現兩個不一致的值（**只抓「多值衝突」，抓不到「單一但錯誤」的值**）
  - 價位宣稱分類比對：歷史低點型（失效線/支撐/前低）比**低點**序列、目標型（壓力/目標/上看）比**高點**序列（只提示）、「下一站」由上下文決定方向、計算型（止損）驗**算術**
  - **雙標的先判歸屬**：每條價位歸給前方最近的標的提及，只比對該檔數列；跨檔錯置或量級不符判 FAIL，無法歸屬列 INFO 並使 exit 2
  - 價位可用整數（「失效線 20」），但日期（`10/23`）、參數（`cooldown=10`）、`T+20`、均線期數、5 位以上代號會被排除
  - n<10 是否仍給小數勝率、免責聲明是否存在

⚠️ 它**不能**驗證估值、事件定義是否合理、或數字是否符合你的商業判斷。報告結構與免責聲明 → `references/reporting.md`

**腳本自身的回歸**（改完代碼、發版前跑）：

```bash
python scripts/selfcheck.py     # docstring import、--help、無參數、未知事件、基準列級別、
                                # Markdown 幽靈檔案、文件預設網格、冷卻期掃描格數
```

## 四、決策門檻（什麼時候必須說「沒有依據」）

這是本 skill 的煞車。**以下任一條件成立，就不得給出「值得進場」的結論。**

| 條件 | 必須說的話 |
|---|---|
| 事件淨期望 < 隨機基準 | 「這個訊號沒有 Alpha，歷史上不如什麼都不看」 |
| 淨期望（扣成本後）< 0 | 「這是負期望交易，倉位管理只會把虧損速度調慢」 |
| 事件 n < 10 | 「樣本不足，只能說方向，不能給勝率」 |
| 近三年勝率 < 50% | 「整體數字被早年牛市拉高，近期環境下不成立」 |
| 形態未在目標板塊重測 | 「這個結論來自其他板塊，不可移植」 |
| 標的仍處真破位序列 | 「這是趨勢延續，不是底部」 |
| 合理倉位 <1 手 | 「波動相對資金過大，這個標的不適合這個帳戶」 |

**遇到這些情況，仍然要把數字算完、把分布給出來**——只是結論必須是「沒有依據」，而不是硬找一個進場理由。

## 七、最常犯的錯（交付前逐項打勾）

- [ ] 用搜索摘要代替逐日數列
- [ ] 事件不去重（虛增約 24%）
- [ ] 路徑模擬把進場價寫死成常數
- [ ] 只報均值不報中位與分位數
- [ ] 跳過隨機進場基準
- [ ] 忘記扣交易成本就宣稱「正期望」
- [ ] 忘記補當日盤中 K
- [ ] `prior_low` 算成含當日（F/G 全漏，輸出假 n=0）
- [ ] 只用單一標的算勝率
- [ ] 合併樣本不按年份拆分
- [ ] 把「長下影」「跌得多」當成進場理由（實測 ≈ 隨機）
- [ ] 把真破位與假破位混為一談
- [ ] 把別的板塊驗證過的 Alpha 直接移植
- [ ] 拿 n<10 的勝率下結論
- [ ] 只給機率，不給失效線
