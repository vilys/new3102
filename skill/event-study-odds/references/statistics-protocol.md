# 統計協議

這份文件定義「怎麼算才算數」。每一步都有必須遵守的算法與必須檢查的偏誤。

---

## 一、前向報酬分布

對每個事件日 `i`，以**該日收盤** `c_i` 為基準：

```
報酬(H) = close[i+H]/c_i - 1
MFE(H)  = max(high[i+1 : i+H+1])/c_i - 1
MAE(H)  = min(low[i+1 : i+H+1])/c_i - 1
```

輸出必須包含 **n / 均值 / 中位 / P25 / P75 / 勝率 / MFE 中位 / MAE 中位**。

**只報均值會騙人。** 這類分布右偏嚴重（存在 +130% 的極端值），均值會被少數暴漲拉高。若均值與中位差距超過 2 個百分點，以中位為主敘述。

常用窗口：T+5、T+10、T+20、T+40。**T+20 是主口徑，其餘作為穩健性檢查。**

---

## 二、路徑模擬（核心）

靜態前向報酬假設你能持有到第 H 天，但真實交易會被止損打斷。必須做路徑模擬。

```python
b = close[i]                       # ⚠️ 各事件自己的收盤，不是統一進場價
u = b * (1 + target/100)
d = b * (1 + stop/100)
for j in range(i+1, i+H+1):
    if low[j]  <= d: → 止損
    if high[j] >= u: → 達標
else:               → 以 close[i+H] 計浮動損益
```

三條鐵律：

1. **進場價不可寫死。** 歷史事件價位從 1.4 到 5.6 都有，把 `b` 固定成「現在的價格」會讓障礙價完全失效，結果退化成全 0 或全負。這個 bug 實際發生過兩次。
2. **同日同時觸及目標與止損 → 判止損。** 日線無法判斷先後，取保守值。
3. **必須扣交易成本。** 未扣成本的「正期望」不是結論。

### 輸出矩陣

```
止損 ∈ {−5, −7, −9, −12, −15, −18} %
目標 ∈ {+8, +12, +16, +20, +25} %
每格：達標率 / 止損率 / 到期率 / 淨期望
```

### 典型結論形態（多標的重複出現）

- 止損越寬 → 被掃率越低 → 淨期望越高，但**超過約 1.8×ATR 後邊際收益歸零**。
- 目標越大 → 淨期望越低（MFE 分布有上限）。
- **貼價止損 + 大目標 = 最差區域**，而這正是多數散戶的默認打法。
- 止損 <1.2×ATR 幾乎必然被噪音掃掉。先算 ATR，再談止損百分比。

## 三、隨機進場基準（照妖鏡）

用同一套路徑模擬，改成「每 20 個交易日無條件進場一次」。

CLI 的 `_print_matrix` 已內建：每一格都會計算同參數（同止損、同目標、同 H、同成本）的基準，
並直接印出「超 +X.XXpp」與裁決。**若某格超額 ≤0，那一格就沒有 Alpha，不能只挑有超額的格子講。**

**這是整個流程最重要的一步，也是最容易被跳過的一步。**

若事件訊號的淨期望沒有顯著優於基準，正確結論是：

> 「這個訊號沒有 Alpha，是位置/板塊/週期在起作用。」

而不是「雖然略低於基準，但……」。

實測案例：某股超賣事件淨期望 +0.76%，隨機基準 +0.94% → 訊號無效。當時若硬拗，就會把雜訊包裝成策略。

## 四、跨標的合併（對抗倖存者偏差）

單一個股的事件數通常只有個位數，單一 ETF 也只有十餘個。**在單一標的上算出的勝率極不可靠，且系統性偏高。**

實測教訓：同一組「長下影探前低」定義，只跑 URA 得到 **勝率 76.5%、MAE 中位 −3.0%**，非常誘人。擴大到 13 個標的後，掉到 **56.3%、−8.9%**。

原因：大型 ETF 天然比小型礦股抗跌。**只測大標的，等於只看了樂觀的那一半樣本。**

正確做法：

1. 選 8–15 個同產業標的：ETF + 龍頭 + 中小型，覆蓋不同波動特徵。
2. 對同一事件定義在各標的上分別取事件，**合併**計算。
3. 每個事件的基準是**它自己的收盤價**。
4. 同時輸出**單標的 vs 合併**兩組數字，讓讀者看見偏差幅度。
5. 路徑矩陣也用合併樣本。

反向陷阱：合併給的是「產業平均」。若目標標的籌碼結構明顯不同（上方套牢極重），實際達成難度高於表上數字，需另行說明。

## 五、分年勝率（時期偏差）

合併多年的樣本**必須按年份拆開**。

實測（鋰礦 F 事件）：

| 年份 | 2018 | 2019 | 2020 | 2022 | 2023 | 2024 | 2025 |
|---|---|---|---|---|---|---|---|
| T+20 勝率 | 71.4% | 57.9% | 81.8% | 83.3% | **42.1%** | **50.6%** | **44.8%** |

合併整體 52.4%，但 **2023–2025 只有約 46%（負期望）**。整體數字被 2018–2022 拉高。

**規則：若近三年勝率 <50%，必須在報告首屏附近標註，且不得用整體數字作為進場依據。**

## 六、成交分布（K 線看不出來的東西）

把近 250 日成交量按價格分桶（桶寬取價格區間的 1/20 ~ 1/24），看兩件事：

- **現價上方累積多少量** → 反彈時的解套壓力
- **現價下方是否稀薄** → 破位時是否進入流動性真空而加速

實測（09696）：**60.5% 成交量堆在 34.5 以上**，24 以下稀薄 → 上方極重、下方真空，屬「反彈難、下跌快」的結構。

另一例（09696，2026-10）：**近一年 99.0% 成交量在現價之上，下方僅 1.0%**。這種結構下，反彈每一步都要吃掉套牢盤，而破位則幾乎沒有承接。

## 七、觸及概率

兩種都給，互為穩健性檢查：

1. **歷史 bootstrap**：對歷史每一天量測其後 H 日的 MFE/MAE，統計超過門檻的比例。
2. **常態近似**：以日波動率 σ 推導 `P(max > x) ≈ 2*(1-Φ(x/(σ√H)))`。

兩者差距大，說明分布肥尾嚴重，**以 bootstrap 為主**。

表述紀律：**「曾觸及」不等於「收盤於該價位」。** 報告中必須寫清楚是哪一種。

## 九、倉位換算

倉位由**風險預算**反推，不是由「我看好」決定：

```
每股風險 = 進場價 × 止損百分比
每手風險 = 每股風險 × 每手股數
手數     = (總資金 × 單筆風險%) ÷ 每手風險
```

必須同時報「連續虧損情境」：被掃率 37.5% → 連三掃機率約 5.3%，不是罕見事件。

⚠️ 若算出來的合理倉位小於 1 手，正確結論是「**這個標的的波動相對你的資金太大**」，而不是「放寬止損讓它能買」。

## 十、樣本量門檻

| n | 可以說什麼 |
|---|---|
| ≥100 | 可以給勝率與期望值，並做分年拆分 |
| 30–99 | 可以給方向與粗略勝率，必須標註樣本量 |
| 10–29 | **只能說方向**，不得給出小數點後的勝率 |
| <10 | 只能當軼事。**禁止用勝率下結論。** |

實測反例：01164 自身只有 3 次假破位（1 成功、1 失敗、1 待定）。這種樣本算出來的「66.7% 勝率」毫無意義。

**這段不是建議，是執行紀律。** `event_study.py` 的 `summary_table` 會依上表處理：

- n<10 → 勝率欄直接印「—」，表尾列為「禁止用其勝率作為進場依據」
- 10–29 → 勝率只給整數（`fmt_win`），並在表尾提示「不得引用小數點勝率」
- n≥30 → 正常顯示

若你看到某個數字仍以小數形式出現在 n<10 的表格裡，那是報告作者手動覆寫了輸出，屬於交付缺陷。

---

## 十一、必須誠實揭露的五件事

1. 樣本量與事件去重方式（冷卻期幾天）
2. 合併樣本跨了哪些年份、近三年勝率多少
3. 「情境平移」的數字屬推導值，不是實測
4. 成本假設與滑價處理
5. 未涵蓋的外生變數（財報、政策、商品價格、利率）
