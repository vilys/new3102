# 報告交付規格

## 一、先決定要不要出報告

| 情境 | 交付形式 |
|---|---|
| 用戶問「值不值得」「概率多少」「支撐在哪」且需要多圖對照 | HTML 報告 + 對話摘要 |
| 單一數字、單一價位、快速確認 | 直接對話回答，不出檔案 |
| 用戶明確說「存成報告」「要來源」 | HTML 報告 |

**不要為了出報告而出報告。** 一次只回答一個價位問題時，長篇報告是負擔。

---

## 二、HTML 報告結構（固定順序）

1. **首屏結論**：值 / 不值得、關鍵三個數字、明確的一句話判斷。
2. **事實校正**：先把用戶的觀察與數據對齊（例如「1.9x 其實只是下影線」）。
3. **形態證據**：K 線標註圖、均線、MACD/RSI/ATR。
4. **統計證據**：事件研究表 + 隨機基準對照（同一張表，不可分開擺）。
5. **路徑與賠率**：止損×目標淨期望熱力圖或矩陣。
6. **價位結構**：支撐/壓力階梯、觸及概率。
7. **基本面與消息面**：只放與價格機制相關的，不寫成公司介紹。
8. **我的判斷與驗證點**：三個可觀察的確認/否證條件。
9. **局限與來源**：樣本、口徑、成本、未涵蓋變數、資料日期。

**第 9 節不是免責樣板，是報告可信度的一部分。** 寫得越具體，結論越可信。

---

## 三、視覺規範

- 有數值軸的圖 → **ECharts**
- 價位結構 / 產業鏈分層 → CSS 盒子或 SVG
- 深色主題下，文字必須淺色；淺色主題下反之。**不要用預設黑字配深底。**
- 每張圖必須有「這張圖在說什麼」的一句話標題，不能只寫「圖一」。
- 圖表數據序列放在 `var X=[...]`，方便自檢器檢查長度。

樣式細節沿用 `wb-finance-skill/references/html-report-style.md`。

⚠️ 該檔案存在於 finance-data **1.5.0**；**1.6.0 已移除**。找不到時回退到 1.5.0 目錄讀取。

---

## 四、交付前自檢（不可跳過）

```bash
python scripts/verify_report.py report.html
```

必須看到 `全部通過（渲染層＋啟發式財務檢查），可交付`（exit 0）。若顯示 **`部分通過，需人工確認`**（exit 2），代表有檢查被跳過或觸發警告，不得對外宣稱已驗證。

**exit 2 的處理政策（二選一，不可默默放行）：**

- **新報告**：必須 exit 0 才能交付。SKIP 要當成待辦，補上 `var/window` 數列或補 node，不要用「我看過了」硬過。
- **舊報告**：允許以 exit 2 交付，但必須逐項記錄 SKIP 原因與人工確認結論，並在該報告的 README 標為「未通過自檢，數字未驗證」。**禁止把 SKIP 改寫成 PASS**——那等於退回「假通過」。

`[INFO]` 不影響 exit code，但它不是裝飾：它表示某條宣稱**無法用現有數列自動驗證**（引用更早的低點、分析師目標價、沒寫進場價的止損），要在交付訊息中一併說明。

檢查分兩層：

**渲染層**
1. 內聯 JS 語法（`node --check`）
2. 各數值數列長度（日期/收盤/RSI 必須同 n）
3. 重複的物件鍵（含嵌套物件；`data: X, data: Y` 這種筆誤會讓整張圖空白）

**財務啟發式**
4. 同一指標（MA/RSI/ATR）是否出現兩個接近但不相等的值 → 通常是混用了不同 cutoff
5. 價位宣稱對回原始 K 線，**分三類**：
   - 歷史低點型（失效線／支撐／前低／觀察線）→ 必須命中低點序列，否則 FAIL
   - 目標型（壓力／阻力／目標／下一站）→ 對高點序列檢查，只提示不 FAIL（可能是分析師目標價或推導值）
   - 計算型（止損／止蝕）→ 不與歷史低點比對，改驗「進場價 × (1−止損%)」的算術
   - 價位落在數列窗口之外 → INFO，不當錯誤（例如引用 2025-04 的低點，而圖只有近 105 根）
   - 支援扁平數列（`L1164`／`LO`／`low`）與巢狀 K 陣列（`[[o,c,l,h],…]`，以「恆為該列最小／最大值」偵測欄位）
6. n<10 卻仍給出小數勝率
7. 免責聲明是否存在

**一處括號失配就整頁圖表全廢。** 這個檢查做過至少三次救回整份報告。

**但它不驗證估值、事件定義是否合理、結論是否符合商業判斷。**

⚠️ **兩個必須講清楚的邊界：**

- 「指標一致性 PASS」**不等於**「指標數值正確」。它只抓「同一指標出現兩個不一致的值」；若全文只有一個錯值（例如 MA20 全部寫成 2.078，而真實是 2.088），它無從比較，會 PASS。
- 「價位對照 PASS」只覆蓋**能被正則抓到、且落在數列窗口內**的宣稱。寫成「1.95 前低」（數字在前）或只存在於圖表軸標籤的價位，不在檢查範圍。

## 五、對話摘要的寫法

報告交付後，對話中要給一份**能獨立讀懂**的摘要：

1. **一句話結論**（值 / 不值得 / 條件式）
2. **三個決定性數字**（表格形式，不要超過三行）
3. **一個反直覺發現**（這是分析的價值所在）
4. **兩個必須說的限制**
5. **失效線**（什麼情況下這份結論作廢）

控制在 50–70 行內。**不要把報告目錄複述一遍。**

---

## 六、必須附的免責聲明

固定模板（可微調，但五個要素不可省）：

> 以上內容基於公開數據和量化分析，僅供參考，不構成投資建議。文中所有概率為歷史統計推導值，且「曾觸及」不等於「收盤於該價位」，不構成對未來表現的承諾或保證。統計數字主要來自 N 個標的的合併樣本平移，非單一標的實測，並存在 XXXX–XXXX 年勝率低於 50% 的時期偏差。市場有風險，投資需謹慎。任何投資決策應結合個人風險承受能力、資金狀況和投資目標獨立判斷，必要時諮詢持牌專業機構。過往表現不預示未來收益。

**「非單一標的實測」這句必須誠實寫。** 用 15 個標的的合併數字去描述一隻股票，是推導，不是測量。

---

## 七、語氣

- 直接給判斷，不鋪陳。「不值得」「等得到」「這是震盪不是單邊」。
- 出現與自己上一輪結論相反的新證據時，**明確說「我上一輪那句是錯的」**，並指出錯在哪。
- 不確定就寫「這是推導值」「樣本不足以下結論」。
- 不寫「綜上所述」「值得投資者關注」這類空話。
